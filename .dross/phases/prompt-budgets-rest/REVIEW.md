## BLOCKING
- [antipattern / self-defeating step] t-1 says to build the base binary with "`go build` there", but `internal/cmd/version.go` defaults `Commit = "unknown"`. Only `make build` (Makefile LDFLAGS `-X ...cmd.Commit=$(COMMIT)`) or an explicit `-ldflags` sets the commit. A plain `go build` binary reports `dross 0.1.0.0 (commit unknown, built unknown)`, so t-1's own contract ("each before binary_version must contain \"commit 8eb38e9f\"") and t-16's `promptBudgetsRestBase` check fail by construction. This is not a cheap failure: the before legs are three human-driven sessions, and they can only run while the prompts are unedited. Once t-5 or t-10..t-14 land, re-capturing means restoring the prompts by hand. Recorded numbers may not be edited ("observed numbers only"), so the binary_version cannot be patched after the fact either.
  Suggestion: Change t-1 to `make build` in the worktree, or `go build -ldflags "-X github.com/Rivil/dross/internal/cmd.Commit=8eb38e9f ..."`. `make install` and `dross test` stay forbidden there. Check `<bin> version` for `commit 8eb38e9f` before driving any leg.
