## BLOCKING
- [coverage/integration] Plan-side citations reach the new plan-lock gate with no prompt path to handle them. t-11 only walks citations **on the spec, before composing** (§1). /dross-plan §6 then runs `dross state set current_phase_status "planned"`, and t-10's gate checks plan `description` and `test_contract` too (locked scanned_fields). Test contracts routinely name fixture files and symbols that do not exist in the tree. An approximate path-only extraction over recent plans finds unresolved fixture paths in every one: milestone-closeout-check 2 (`f.go`, `g.go`), spec-edge-probe 1, review-edge-lenses 6, scoped-commit-gate ~20, and this plan ~11 (`foo.go`, `x.go`, `a.ts`, `nosuch.go`, `internal/x.go`…), plus symbol fixtures such as `wrongpkg.Index` and `quoted.String()`. That count is approximate: it read `git ls-files`, so it over-counts machine-local files such as `state.json` that exist on disk but are untracked. Even so, with t-10 + t-11 as written, nearly every /dross-plan run would fail at §6 with a refusal the prompt never mentions. The agent would have to improvise a second walk or hand-edit `new`, which is the misplaced-key trap t-4 contract 3 pins.
  Suggestion: widen t-11's scope (files already include plan.md and the partial) so §6 handles a facts refusal at lock time. Re-run the same one-per-turn walk over the plan-side findings, then re-lock. Add a plan_prompt_test assertion that §6 names the walk. If the user would rather take this as a follow-up quick, record that decision explicitly. Shipping it silently is the wrong outcome.
