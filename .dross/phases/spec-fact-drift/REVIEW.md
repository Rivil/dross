## BLOCKING
- [coverage depth: c-1 / false positives] Bare basenames of gitignored files will be reported missing even when the file exists. t-6 resolves a bare basename against "the t-3 walker output". t-3's walker is `git ls-files --cached --others --exclude-standard`, and its own contract pins that gitignored files are absent. In this repo `.dross/state.json`, `.dross/local.toml` and `.dross/handoff.md` are all gitignored (.gitignore:12/17/23). A scan of the locked scanned_fields (criteria text, decisions choice, task description/test_contract) across existing phases finds 214 bare citations of them: `state.json` 138, `local.toml` 53, `handoff.md` 23. They appear in 51 of 151 phase dirs, including this plan's own t-10 contract ("state.json's current_phase_status"). Each one would be reported "missing" although the file exists in the working tree, which contradicts c-1's "does not exist in the tree". t-10 then turns each into a plan-lock refusal. The only remedy the plan offers is `dross phase mark-new`, which records a false claim ("new in this phase") in `spec.New`. t-6 already sees this problem for slashed paths ("checked on disk via pathfence.Stat so gitignored machine-local files still resolve"), but the bare-basename branch doesn't get the same treatment.
  Suggestion: in t-6, make the bare-basename lookup also consult ignored files that exist on disk, for example a second `git ls-files --others --ignored --exclude-standard` list used only for basename existence, never for the symbol index. Add a t-6 contract: in a temp git repo where `.dross/state.json` is gitignored and present, bare `state.json` resolves, and a gitignored `dist/a.go` still stays out of t-5's index.

## FLAG
- [antipattern: unspecified behaviour] Nothing says how a bare-basename file:line citation chooses its file for symbol classification. That is the commonest citation form here: 532 bare `name.go:N` citations sit in scanned fields of existing specs and plans, and 157 of them use a basename that is not unique in the tree. Examples: `phase.go` 27, `verify.go` 21, `state.go` (internal/cmd vs internal/state). t-3 extracts these as a bare basename, and t-6 settles existence for path-kind only. t-5 and t-7 don't say whether a paired `` `planLockEdgeGate` — state.go:349 `` looks up symbols by unique basename, joins it onto the repo root (always Gone), or skips it. t-7's end-to-end contract uses a root-level `x.go`, which passes under all three readings, so the contract can't tell them apart.
  Suggestion: state the rule in t-5 or t-7. The rule consistent with c-3's "ambiguous is never reported" is: a unique basename resolves to that file; an ambiguous basename makes the citation Skipped. Add a contract with two `state.go` files in different dirs.
- [coverage depth: c-4 / c-5] Review amendments get past both the facts walk and the gate. In plan.md, §6 sets `current_phase_status planned` (the gate fires there), then §6.1 runs the plan review. A BLOCKING result sends the author back to "rewrite plan.toml, re-validate", with no re-lock and no facts re-run. Amendments routinely add new test-contract citations; this phase's own amendment added `../../etc/passwd`, `.claude/worktrees/w/`, `install.ps1` and `a.ts`. None of them would ever be checked. t-11's §5 re-run comes before the lock, so it never sees the amended plan.
  Suggestion: extend t-11 so the §6.1 BLOCKING-amendment path re-runs `dross phase facts <id>` and the same partial walk after the rewrite. Add a plan_prompt_test assertion that the 6.1 amendment bullet names it.
- [test contract / integration] t-9's `mark-new` may not be able to accept a symbol citation. It normalises "via facts.Extract", but t-3's locked symbol_shape extracts a standalone symbol only from a *backticked* token. Argv usually arrives without backticks, because an unquoted backtick in a shell is command substitution, so Extract(`quoted.String()`) yields nothing and mark-new refuses. Yet t-7 expects `spec.New ["pkg.Name"]` to suppress `` `pkg.Name()` ``, and t-11's walk offers "confirm new via `dross phase mark-new`" for every finding kind. Every t-9 contract uses a path (`foo.go:12.`, `fooo.go`).
  Suggestion: say in t-9 how a bare symbol argument is normalised (for example, try it as a backticked token when path extraction yields nothing), and add a contract: `mark-new <id> 'quoted.String()'` stores `quoted.String` and the next facts run exits 0.
- [coverage depth: c-3] t-5's Degraded census is all-or-nothing, so a single root config file turns c-3 off for a whole repo. Almost every TS or Svelte project carries `vite.config.js`, `svelte.config.js`, `postcss.config.cjs` or `eslint.config.js` outside testdata/fixtures. Kotlin and Dart are on the census list too. So on every non-Go stack the author works in, the index is permanently Degraded and every unmatched symbol is Skipped, even with ast-grep installed. It is honest because t-8 says so, but in practice the motivating `quoted.String()` check would only run in pure-Go repos.
  Suggestion: decide this explicitly. Either accept that it's Go-only and record that in t-5 so verify doesn't claim c-3 broadly, or narrow the census, for example by ignoring root-level `*.config.{js,cjs,mjs}` files or by skipping only symbols whose qualifier isn't a package the index knows.
- [antipattern: copy-the-neighbour trap] t-10 says to mirror `planLockEdgeGate`, but the root it is given is the `.dross` dir, not the repo. `planLockEdgeGate(filepath.Dir(path), …)` receives `FindRoot()`'s value, which is `<repo>/.dross` (root.go:83–90, `state.File = "state.json"`). `facts.Check(repoDir, …)` needs the repo root for the walker and Stat. A gate written by copying the edge gate's argument would report every repo path missing. The parity table would probably catch this, but the description doesn't state it.
  Suggestion: in t-10's description, state repoDir = `filepath.Dir(root)`, the same derivation t-8 uses. One parity row citing a real repo file such as `internal/cmd/state.go` then pins it.
