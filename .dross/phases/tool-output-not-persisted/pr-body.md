## Decisions locked

- **cut_point** 🔒 — The cut is at error construction, not at the persistence boundary. Adapters never build an error string containing tool output: stryker prints the head quote to stderr at the failure point and returns a structured error, so nothing downstream needs to scrub. *(A scrubber can only strip shapes it was told about, so not creating the string is the stronger guarantee, and it matches the milestone's 'captured subprocess output is not persisted at all' half. A boundary scrub would also leave the raw string live in memory for any new writer to pick up.)*
- **stderr_pointer** 🔒 — The recorded pointer is fixed prose naming the tool and stating that its full output went to this run's stderr. No log file is written and no path is recorded. *(dross cannot know where its own stderr was redirected — nohup, CI capture, a detached remote run — so a recorded path would often be wrong. Writing a log file would re-persist exactly what the milestone forbids.)*
- **guard_shape** 🔒 — Declare the sinks, enumerate the writers: a registry names the persisted fields that may carry tool-derived text, and the guard walks every assignment to them, failing unless the value came from the shared recorder. Source-side enumeration of exec-derived strings is out of scope. *(Tractable with go/ast, and it is the registry-plus-residual shape tracked-path-containment already proved. Source-side enumeration is a far wider reach analysis over a codebase that spawns git everywhere.)*
- **terminal_requote** 🔒 — The headBuffer stays. On a failure the head of the tool output is re-printed to stderr at the failure point, exactly as it is quoted into the error message today. *(The quote exists because the cause sits at the HEAD of a long stream the user has already watched scroll past. Dropping it on the grounds that the stream teed live would regress the diagnosis c-3 promises to keep unchanged.)*
- **no_migration** 🔒 — New runs only — no migration pass over existing artifacts and no scrub on read. *(No verify.toml or tests.json on disk currently records a leg error, so there is nothing to migrate, and both files are rewritten by every verify run.)*
- **renderable_derivation** 🔒 — A persisted field derived from a recorded field — verify.Finding.Text, composed as "mutation adapter <tool> failed: " + LanguageRun.Error — is declared Renderable and may be rendered by a PR or board composer. c-5 and c-6 bind the declared subprocess-derived fields themselves, not values derived from a record whose own text is already scrubbed. *(Finding.Text is how a failed leg reaches a human at all; forbidding it would delete the Findings section from every PR body while removing no tool output, because the record it interpolates carries none. The exception is only as safe as the pin that keeps it derived, so it is checkable rather than asserted: t-8 pins verify.toml's finding.text to exactly the recorder line under that prefix, and a composer interpolating anything else fails there.)*
