## BLOCKING
- [antipatterns/shim-closure] t-3 says both "`configuredAdaptersFn = configuredAdapters` stays literal" (a production `var` at internal/cmd/verify.go:1018) and "TEST-ONLY SHIM: internal/cmd/mutationcfg_shim_test.go defines `configuredAdapters(p, root, skip)`". Those cannot both hold: if `configuredAdapters` exists only in the `_test.go` shim, `go build ./...` / `make build` / `go vet` fail with `undefined: configuredAdapters`; if production keeps a `configuredAdapters` wrapper so the seam compiles, the shim's definition is a duplicate symbol and the test build fails. The 6+3 direct calls in mutation_remote_wiring_test.go / remote_preflight_wiring_test.go are the ones the shim exists for, so this is exactly the seam the fix was meant to close.
  Suggestion: keep `configuredAdapters(p, root, skip)` as an unexported production wrapper in verify.go (it is a three-line call to `mutationcfg.Configured(p, root, skip, localSource(root))`, adds nothing to the export surface, and keeps the seam var literal), and reduce the shim to `resolveMutationTuning` and `remoteMutationTools` only. Alternatively initialise the seam with a closure — but then the wiring tests still need the shim and the "stays literal" sentence must go.
- [antipatterns/files-not-yet-existing] t-6 moves toolfence_composer_test.go into internal/boardsync in wave 2, but that test calls `renderTaskBody("p", "DRO-1", plan.Task[0])` directly (internal/cmd/toolfence_composer_test.go:98), and `renderTaskBody` (internal/cmd/issue_task.go:303) does not move until t-9 in wave 3. A boardsync test cannot reference a cmd symbol (import of internal/cmd is both a cycle and the thing t-10 forbids), so internal/boardsync does not compile at the t-6 commit. t-9's own text ("toolfence_composer_test.go already lives in boardsync after t-6, so its renderTaskBody call becomes intra-package") describes the state after t-9, not the state t-6 must be green in.
  Suggestion: move toolfence_composer_test.go in t-9 instead of t-6 (its three composers are then all in boardsync, with composerRoots = {".", "../ship"}), or move renderTaskBody + its helpers in t-6 alongside renderPhaseBody. Either way, remove it from t-6's files and contract line 3 ("moved TestNoBodySinkReadsARecordedField ... proves the composers moved intact") until the task that actually lands it.
