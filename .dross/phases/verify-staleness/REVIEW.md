## FLAG
- [wave-order] Nothing in the plan says which task owns the `measuredTreeFn` seam. t-4 declares it in `internal/cmd/verify.go`. t-5 runs in wave 2 alongside t-4, with `depends_on = ["t-1","t-2"]`. t-5 does not depend on t-4, and its description says verdictFreshness "takes MeasuredTree". t-7's `TestStatusStaleSilentOnError` stubs `measuredTreeFn` so that verdictFreshness fails, but that only works if t-5 routes through t-4's seam. If t-5 calls `treefp.MeasuredTree` directly, the t-7 clause can't be met without editing `verdict_fresh.go`, which is not among t-7's files. If t-5 declares its own seam, two package-level vars land in `package cmd` and the build breaks. The panel synthesis had t-5 depend on t-1, t-2 and t-4, and that dependency was lost when plan.toml was written. t-7 also stubs the seam but lists only t-5 as a dependency.
  Suggestion: Pick one owner. Option (a): t-5 gets `depends_on += "t-4"` and calls `measuredTreeFn`; t-5 moves to wave 3 and t-7 to wave 4. Option (b): drop the `measuredTreeFn` clause from t-7 and get the error another way, using the non-git root it already lists or a git stub on PATH (as TestEveryGitCallIsBounded does). Option (b) keeps 3 waves.

- [test-contract] t-5's description says "a capture error refuses", but none of its 13 tests produces a capture error at ship. Only unlistable-diff and malformed-tree failures are pinned, so the fail-closed path for the tree capture itself is untested. A related risk: if verdictFreshness captures the tree before Classify sees that no tree is recorded, a capture failure on a legacy verify.toml refuses. That would break the locked `legacy_freshness` decision ("ship warns and proceeds"). t-2's `TestClassifyLegacyIsUnknownWithoutGit` guards Classify, but nothing guards the capture that happens before it.
  Suggestion: Add `TestShipRefusesWhenTheTreeCannotBeMeasured`: a recorded tree plus a capture error should refuse and push nothing. Add `TestShipLegacySkipsCapture`: no recorded tree plus a capture error should exit 0 with the unknown warning. State in t-5 that verdictFreshness returns unknown before it captures anything.

- [test-contract] t-5's ordering tests don't check the placement they claim to. `TestShipRefusesAStalePass` runs `ship --no-push`, which returns before `repointDoomedRedProofs` and `autoCommitDrossDirt` wherever the gate sits, so its "HEAD unchanged" assertion can't fail. `TestShipStaleRefusalPushesNothing` checks only the remote side (origin, POST /pulls, changes.json). A gate placed after `autoCommitDrossDirt` but before the push passes every listed test while leaving a local .dross commit behind. Nothing checks that `--print-body` refuses either.
  Suggestion: In the full-flow refusal test, leave a dirty `.dross` file and assert HEAD did not move and no repoint commit was made. Add one assertion that `--print-body` on a stale pass exits non-zero.

- [correctness] t-7 replaces only the final `/dross-ship` branch of `suggestNext`. In `status.go:302-326`, the `mergeOpen` and `CurrentPhaseStatus == "shipped"` branches return earlier ("merge the open PR, then `dross phase complete`"). A stale pass in the PR-open window therefore gets a `stale:` marker and a footer telling the user to merge. That window is exactly where c-7's CI fixes happen. Separately, `TestStatusNoMarkerFromMain` checks only the marker line. If the HEAD-on-phase-branch guard is left out of `suggestNext`, a SessionStart on main compares main's tree, reads stale, and suggests `/dross-verify`, and that test still passes.
  Suggestion: Run the stale check (on the phase branch) before the merge-state branches. Add a test with a shipped phase and a stale pass whose footer names `/dross-verify`. Extend `TestStatusNoMarkerFromMain` to check that the footer still matches the non-stale suggestion.

- [stale-docs] t-7 brings back a `stale:` line in `dross status`. `assets/prompts/resume.md:34` tells the agent "There is no `stale:` line to look for any more", so `/dross-resume` will be misled the first time the new marker appears. Two existing guards in `status_test.go` assert no `"stale:"`: `TestStatusReportsShippedNotStale` and `TestStatusSilentAfterCompletion`. They will still pass, because their fixtures are legacy (no recorded tree), but their premise ("a shipped phase is not stale") is no longer true. No task touches resume.md.
  Suggestion: Add `assets/prompts/resume.md` to t-7 or t-3 and rewrite that sentence to describe the verdict-staleness marker, keeping the "stale" and "completed" needles that `TestResumePromptStaleStateSection` requires. Alternatively, use a label that can't be confused with the old one (e.g. `verdict:   stale — …`).

- [hidden-ratchet] The repo-wide spawn-output taint gate (`TestNoSpawnOutputEscapes`, `taint_audit_test.go`) scans `internal/treefp` (treefp.go already carries `//dross:taint-cleared` markers). MeasuredTree adds new git output that gets saved to disk: the HEAD sha for `Commit`, plus its own write-tree output if it doesn't reuse `tree()`. That output ends up in tests.json, verify.toml and local.toml's DetachedRun. t-1's test contract names `TestEveryGitCallIsBounded` and `TestRealIndexUntouched` but not this gate, so execute will likely hit it as a surprise red at the commit gate.
  Suggestion: Add a t-1 contract line: "if the new HEAD/tree reads persist unmarked, TestNoSpawnOutputEscapes fails". Mark each conversion with a reasoned `//dross:taint-cleared`.

- [granularity] t-3 touches 5 files and mixes two jobs. One is c-7: the ship.md §5 and §6 re-ship order and its prompt tests. The other is documentation of behaviour that waves 2–3 build: the README rows for verify, verify results, status and ship; the §0/§4 wording of the stale refusal; and the verify.md keep-pin. Writing the status and ship wording in wave 1, before t-5 and t-7 fix the refusal and marker text, invites drift that no test catches.
  Suggestion: Keep the c-7 ship.md order and its tests in t-3, and move the README rows and the §0/§4 refusal wording into a small wave-3 doc task (or into t-7). Otherwise, add a t-7 step to re-read t-3's wording against the final strings.

## NOTE
- [strength] Classify is pure, with `currentTree` and `diffFn` passed in. That lets the verdict model run in wave 1 next to treefp. The tests.json fallback (taken only when `generated_at` matches) is a sound defence against a verify.toml that loses `measured_*` through the /dross-verify hand edit or a Load→Save from an old binary.
- [strength] The test contracts name the specific failure each test catches: look-alike exemption paths (`docs/ARCHITECTURE.md`, `ARCHITECTURE.md.bak`, `sub/.dross/x`, `.drossrc`), malformed ids that look like flags (`--output=x`, `HEAD`), a 25-file refusal that must not truncate, and `TestMeasuredTreeIgnoresCommitMoves`. The last one pins the subtle requirement that committing exactly the measured dirty changes keeps the verdict fresh.
- [strength] The gate placement is deliberate: after the branch check, before any side effect, with the off-branch refusal winning. Detached runs carry the tree captured at dispatch through the run record, which follows the locked `detached_baseline` decision exactly.
- [accepted-residual] `repointDoomedRedProofs` commits a non-exempt doc (e.g. `fixtures/hostile-config-c5/RUN.md`). After any ship that repoints, the §6 re-ship that c-7 now requires will refuse the verdict as stale. The panel synthesis accepts this, but plan.toml and the planned ship.md wording never mention it, so the user will hit it unannounced.
- [scope] A stale pass can be refreshed with `dross verify --skip-mutation`. That stamps a new tree without re-measuring mutants, and status.md even suggests `↳ --skip-mutation` beside `/dross-verify`. So the gate proves the phase was re-verified, not re-mutated. Separately, `--reuse-report` stamps the current tree onto a stryker report produced earlier. Both come from the spec (c-1 includes `--skip-mutation`); this plan doesn't create them, but they are worth knowing.
- [hook-cost] With t-7, `dross status` and the SessionStart `dross reentry` run `git add -A` into a scratch index, writing loose objects for every modified or untracked file, whenever HEAD is on the phase branch. status.md says status is read-only. The cost is acceptable for this repo, but it is not documented, and on a large untracked tree it is limited only by treefp's 30s per-call Timeout.
- [naming] t-1 says "anchored at dir (the dross root)". In `internal/cmd`, `root` is the `.dross` directory itself (`FindRoot`), not its parent. The plan should say `repoDir = filepath.Dir(root)` so nobody passes `.dross` to MeasuredTree.
- [contract-clarity] t-6 has `detachRecorder.install` stub `measuredTreeFn`. But the extended `TestVerifyDetachDispatchesThroughTheCommand` also calls `install`, and it asserts `record.Tree == MeasuredTree(dir).Tree`. It has to restore the real seam (or the stub has to pass through) to prove the real capture is wired. `TestDispatchSpawnFailureLeavesNoRecord` does not exist yet, though the contract refers to it as if it did.
- [edge] t-2's malformed-id check should accept 64-hex ids as well as 40-hex. Otherwise every ship in a SHA-256 object-format repo refuses its recorded tree as malformed.
- [granularity] t-6 also touches 5 files, but they belong together (record field, dispatch/collect, two tests, two not_paths rows). Splitting it would add a wave whose only file is `cmd/verify.go`. Leave it as one task.
- [r-01] Run `make install` before running /dross-verify on this phase. With an outdated installed binary, this phase's own verify.toml records no tree, and its ship takes the legacy-warning path, so c-2 is never tested for real.
