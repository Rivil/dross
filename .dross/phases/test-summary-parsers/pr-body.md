## Decisions locked

- **gradle_green_counts** 🔒 — A green gradle summary prints gradle's own outcome and task lines (`BUILD SUCCESSFUL · N actionable tasks`); no test count unless gradle printed one. No JUnit XML reads, no injected init script. *(Without testLogging gradle prints no green test counts; XML is stale-prone and stays on the remote host, and an init script would rewrite the repo's test_command.)*
- **mixed_runner_segments** 🔒 — When several parsers claim one segment, merge them: each runner's counts on the summary line, the union of failures under the one MaxBlocks budget. A parser claims only on its own terminal summary line. *(feastahead's bare run is vitest + flutter test in one spawn; today's ambiguous-claim fallback would deny it a summary. Strict claims keep console noise from forging a runner.)*
- **reporter_formats** 🔒 — dart/flutter: parse both the compact and expanded reporters. pytest: parse both default and -q output. *(The non-tty default differs from the interactive one, and wrapper scripts choose the flags; dross can't add them.)*
- **fixture_provenance** 🔒 — Parser fixtures are captured from live runs in equerry (gradle), feastahead (flutter + vitest) and sunday-rider (pytest); red fixtures come from a local, uncommitted test break. *(The original deferral reason was 'no live repo to prove them against'; synthesized fixtures would re-open that gap.)*
