Reviewed: 2026-09-30

This is round 2. The claims below that are marked "probed" were tested against a throwaway `git archive HEAD` copy with a minimal lister, SplitPRs and watch wiring added. They were not worked out by reading the code alone. The repo itself was not modified.

## BLOCKING
- [test-contract / gate correctness] t-4's taint contract is wrong for the natural implementation of t-3's own age formula. The contract says that with watch wired and NO marker in openprs.go, TestNoSpawnOutputEscapes reports zero findings, and that re-adding the marker fails TestGhMarkersAreLoadBearing. Probed at the t-4 state with `age := now.Sub(p.CreatedAt) / 24h` in internal/watch/prs.go, which is the "floor((now−CreatedAt)/24h)" that t-3 specifies:
  - Without the marker, TestNoSpawnOutputEscapes FAILS: `internal/watch/prs.go:30: spawned-process output is passed to (time.Time).Sub (origin internal/ship/openprs.go…)`. `time` is not in `taintTransformPkgs`, so passing a gh-derived `time.Time` as an argument to any `time` function (`Sub`, `Since`, `Parse`) counts as an escape.
  - With the marker, both gates PASS. The marker is load-bearing at t-4, not dead.
  - Writing the same maths with the tainted value as the receiver, `-p.CreatedAt.Sub(now)`, makes the finding disappear. The engine then sees a receiver-only call, and the int64 Duration it returns counts as cleared.
  - So the contract can only be met literally by reordering `Sub`'s operands to get past the gate. As written, it rewards gaming the taint engine. The render path was not the problem: `render.MarshalJSON` → `Print` and the human `Printf` produced no finding, which matches round 1's probe. Round 1's probe had no age computation, which is why it missed this.
  The description's hedge ("if the real render path reaches a non-terminal sink the marker stays") would catch this, but the test_contract states the opposite without any condition, and verify checks the contract.
    Suggestion: restate t-4's taint contract as follows. The t-1 marker STAYS in openprs.go. With it in place, TestNoSpawnOutputEscapes and TestGhMarkersAreLoadBearing are both green. Removing it produces the `(time.Time).Sub` escape in internal/watch/prs.go. Drop the "remove the marker" instruction from the description, and add one line: age is computed in the direct `now.Sub(CreatedAt)` form, never with operands reordered to avoid the gate.

## FLAG
- [antipattern: name collision] `ship.OpenPR` already exists. It is the exported dispatcher `func OpenPR(opts OpenOpts) (*OpenResult, error)` at internal/ship/open.go:51. The plan uses the same name for the new record type in t-1's description ("decode into ship.OpenPR"), in t-1's pathfence contract ("every string field of ship.OpenPR"), and in t-3's signature `SplitPRs([]ship.OpenPR, now)`. The probe failed to compile: `OpenPR redeclared in this block`.
    Suggestion: pick a free name (for example `ship.OpenPRRecord`) and use it consistently in t-1's description and contract and in t-3's description, so the not_paths rows and the SplitPRs signature match.
- [coverage: stale surfaces] t-2 updates "README watch rows". Today the README `dross watch` row (README.md:247) repeats the cobra `Short` word for word: "Read-only digest of board inbound + phase drift since the last tick". No task touches `Short` in internal/cmd/watch.go, its golden cmd/dross/testdata/cli_tree.txt:361, or the shim description in assets/commands/dross-watch.md ("digest of new board issues + phase drift"). If the README row gains PRs, README and `dross watch --help` disagree. If it doesn't, the help text and the skill description still describe a digest that covers only board and drift.
    Suggestion: decide one way. Either `Short` and the shim stay as they are and the README `dross watch` row stays in sync with them, or add cli_tree.txt (plus the Short edit) to t-4's files and the shim to t-2's files.
- [test-contract specificity] Nothing pins the production `prListTimeout`, and every contract in the plan runs against a stub. Failure is quiet by design (c-3), so an undersized timeout, a gh version without `author.is_bot`, or a statusCheckRollup decode mismatch would all look the same as "gh unauthenticated": both keys absent forever, with no diagnostic. There is a cheap live discriminator right now. This repo has one open human PR (#133, `feat/…`) and no bot PRs. I checked with gh 2.97.0: a read-only `gh pr list` returns `author.is_bot` and `statusCheckRollup` items with `__typename`/`status`/`conclusion`. A correct build therefore prints `"bot_prs":[]` and `"ship_prs":[]`, present and empty, while any of the defects above prints neither key.
    Suggestion: pin the `prListTimeout` value in t-1. Add one t-4 contract line: after `make install` (r-01), a live `dross watch --json` on this repo contains both keys as present arrays.
- [test-contract specificity] Two prompt-test contracts claim more than a substring check can deliver. First, TestWatchPromptBotPRLine is described as failing if the template is "moved" out of §2's render block, but it is anchored only as "before 'locked precedence'". That anchor also covers §1, so moving the template into the §1 field bullets still passes. Second, TestWatchPromptNamesEveryDigestField is described as failing when a field is added without updating the prompt. That only holds for distinctive tags. `number`, `title`, `url`, `head` and `checks` will all appear in the new prose or templates anyway, so a new or renamed field with a common-word tag passes.
    Suggestion: anchor the §2 checks between the `## 2.` and `## 3.` headings. For the reflection test, match each tag as a backticked token (`` `age_days` ``) in the unstripped file rather than as a bare substring of the lowercased, backtick-stripped content.
