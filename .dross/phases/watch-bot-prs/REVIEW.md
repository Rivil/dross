# Plan Review — watch-bot-prs

Reviewed: 2026-09-30
Plan: 4 tasks across 3 waves

## BLOCKING
- [test-contract / gate correctness] The taint-marker placement is backwards at both ends, so t-1 and t-4 each fail the full-suite gate as written. I checked this in a throwaway copy of HEAD, not by reading code. The repo declares no `[[runtime.test_lane]]`, so every task gate runs the whole suite, including internal/cmd's taint gates.
  - **t-1 (no marker, per its description):** the taint engine treats a return from any function with no live caller as an escape: "a tainted value returned from a function nothing in the program calls — an unused export … is an escape" (taint_engine_test.go:65). The load uses `Tests: false`, and at t-1 nothing calls `ListOpenPRsFunc`, so the decoded return escapes. The probe was an exported lister behind a var seam: screenedGH → `Cmd.Stdout` buffer → `json.Unmarshal` → return. Without a marker it failed `TestNoSpawnOutputEscapes` with `spawned-process output is returned from …ship.ListOpenPRsProbe to a caller outside the program`. With the marker in place at this stage, both `TestNoSpawnOutputEscapes` and `TestGhMarkersAreLoadBearing` passed, so the marker is load-bearing at t-1. The panel's premise ("a t-1 marker would clear nothing") is false.
  - **t-4 (marker lands here; contract says deleting it "yields a gh-origin finding escaping through watch's render"):** the engine classes `fmt.Print*` and writes to os.Stdout as *terminal*, not as escapes (taint_engine_test.go:52–54). `cmd.Print` and `cmd.Printf` are `fmt.Println` and `fmt.Printf`. I wired the probe into `watch.go` through both the human `Printf` and the `--json` `render.MarshalJSON` → `Print` path. With the marker present, `TestGhMarkersAreLoadBearing` then FAILED: `removing the marker at openprs_probe.go:42 leaves no gh-origin finding — it clears nothing a gate would see`. Without the marker, both gates passed. A marker whose only consumer is watch's stdout render is dead, so t-4's taint contract asserts the opposite of what the engine does.
    Suggestion: put the `//dross:taint-cleared` marker in t-1 and add a t-1 contract saying the unmarked decode fails `TestNoSpawnOutputEscapes`. In t-4, remove the marker once watch is wired, and replace the taint contract with one that holds: "`TestNoSpawnOutputEscapes` reports zero findings and `TestGhMarkersAreLoadBearing` stays green with no marker in openprs.go; re-adding one fails `TestGhMarkersAreLoadBearing`." Re-run both gates on the real SplitPRs/render path before committing t-4. If some part of it reaches a non-terminal sink (an error, a file, a package var), the marker stays, and that sink needs explaining.

## FLAG
- [antipattern: missing file] New JSON-tagged string fields fail `TestEveryPathShapedFieldIsDeclared` unless they are filed in `internal/cmd/testdata/pathfence_scan/not_paths.txt`, and neither t-1 nor t-3 lists that file. I checked this on the probe: `undeclared serialized string field ship.OpenPRProbe.Title … paste this row into testdata/pathfence_scan/not_paths.txt`. In t-1 this covers ship.OpenPR, its author sub-struct and the statusCheckRollup item fields. In t-3 it covers every string field of watch.BotPR and watch.ShipPR, following the existing `watch.Item.Title title` and `ship.BasePR.Title title` rows. execute.md §2 says "Touch only files in `task.files`… pause and ask", so both tasks would stop on a plan deviation.
  Suggestion: add `internal/cmd/testdata/pathfence_scan/not_paths.txt` to the `files` of t-1 and t-3. Add a contract line to each: the new rows are filed under the `ship` and `watch` sections, and none of the fields is a path.
- [test-contract specificity] t-1's argv contract says `--limit 100` is required because "gh's default 30 truncates silently". 100 also truncates silently, and c-1 promises "every open PR whose author the forge marks as a bot". No contract says what happens at the cap. A repo with more than 100 open PRs would silently drop bots and understate `oldest Nd`.
  Suggestion: pick a behaviour at `len == limit` and pin it with a contract: treat the result as incomplete (absent, per c-3), or accept the cap and record it as a known limit in the plan or spec. Either is fine. The current state is an unexamined gap next to a comment claiming the gap was closed.
- [test-contract specificity] The "quiet failure" contracts (TestListOpenPRsFailureIsNilAndQuiet and the TestGhFailureOutputGoesToStderr exception case) only check that dross's own `ghStderr` writer gets zero bytes. They don't cover the spawned gh's inherited stderr fd. An implementation that sets `cmd.Stderr = os.Stderr` would print gh's auth nag to the terminal on every `/loop` tick, which is exactly what "quiet" was chosen to avoid, and every listed test would still pass.
  Suggestion: add an assertion that the `*exec.Cmd` handed to Start has `Stderr == nil` (or a discard or capture buffer that is never echoed). Or run the failing stub with a stderr canary and check that the canary is absent from the test process's captured `os.Stderr`.
- [test-contract specificity] TestWatchPRsAbsentWhenForgeUnreachable compares stdout "byte-identical to the same fixture with [remote] unset". In cmd fixtures `[remote].url` is also the board host allowlist: `boardRepo` sets `remote.url` to the board's httptest URL for that reason (issue_test.go:32–37). On any board-reached fixture, unsetting `[remote]` flips `board_ok` and the new/current feed, so the test fails for a reason unrelated to PRs. The only way to make it pass is a board-off fixture, which drops the board half from that comparison.
  Suggestion: in the baseline, unset only `remote.provider` (keep `.url`), or state explicitly that this comparison runs board-off and that the separate "seam-[] minus bot_prs/ship_prs equals seam-error" clause is the board-reached check.

## NOTE
- [coverage] Every spec criterion is covered, including the ones spread across the ship → watch → cmd → prompt split. c-1: t-1, t-3, t-4. c-2: t-2, t-3, t-4. c-3: t-1, t-2, t-4. c-4: t-1, t-3, t-4. c-5: t-1, t-3, t-4 (with t-2 for the prompt render). All three locks are respected and each has its own test: forge_scope (TestListOpenPRsUnsupportedProviders, TestWatchPRsUnsupportedProvider), pr_suggestion (TestWatchPRsNeverSteerSuggestion, TestWatchPromptPRsAreInformationOnly), pr_age (createdAt pinned in the argv, TestPRRecordJSONKeys rejects any threshold field).
- [wave order] The waves are correct and minimal. t-2 runs in parallel with t-1. t-3 needs t-1's `ship.OpenPR`. t-4 depends on t-2 only because TestWatchPromptNamesEveryDigestField reads the prompt, and it declares that dependency instead of relying on wave numbering.
- [strength] The gh argv is pinned exactly, and each field has a stated reason: `createdAt` over `updatedAt` follows from the pr_age lock, and `isCrossRepository` stops a `phase/evil` fork head from showing up as a ship PR on a public repo. I checked it against gh 2.97.0. All eight `--json` fields are valid for `gh pr list`. A live read-only `gh pr list --json author` on this repo returns author keys `{id, is_bot, login, name}`, which matches the canned fixture's `is_bot`.
- [strength] Absent vs. empty is tested at every layer where it could collapse: the lister returns `(nil, err)` and never `([], nil)` on failure, raw stdout must contain `"bot_prs":[]` with no `null`, and the no-remote golden must pass UNEDITED. The hang test is also correct: the `sleep 30; true` grandchild really does hold the stdout pipe, so it catches a missing `WaitDelay`.
- [strength] Classification, age arithmetic and the digest strings live as pure functions in internal/watch, so the boundary tables (47h59m/48h, +05:00 offsets, `Phase/X`, fork heads) run in the fast package instead of the internal/cmd suite that hangs locally.
- [observation] Quiet failure means an unauthenticated or missing gh leaves `bot_prs` and `ship_prs` absent forever with no diagnostic anywhere. `dross doctor` has no gh check, and the prompt tells the model to print nothing when the keys are absent. The same happens if the production `prListTimeout` is too tight for a 100-PR `statusCheckRollup` query, and the plan doesn't pin that value. This is sanctioned by c-3 ("rest of the digest is unchanged"), so it is not a plan defect. It is worth knowing when the feature appears to "never fire".

## Summary
The plan is well-scoped and its contracts are unusually sharp, but it cannot run as written: the taint marker is inverted (t-1 goes red without it, t-4's marker is dead with it), and t-1 and t-3 both leave out the pathfence not_paths file they will have to edit.
