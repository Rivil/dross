## FLAG
- [wave-order] t-3 and t-4 are both in wave 2, and each contract leans on the other's output. t-3's TestTemplateRoundTrip asserts "no template placeholder satisfies the --fixed gate". The --fixed gate is t-4's FixedCloseGaps. t-4's TestFixedCloseGaps row "(2, Prevention = template comment …)" needs t-3's Template. If the t-3 assertion goes through FixedCloseGaps, it cannot be green before t-4. If it only uses Parse fields, it repeats "0/0/0, empty Prevention" from the same contract.
  Suggestion: pin t-3's placeholder assertion to Parse's Signals/Prevention (t-1 surface) and have t-4 use a literal comment fixture. Or move the "Template → FixedCloseGaps yields both gaps" check to t-5, where both exist.

- [test-contract] t-4's reason-injection contract only tests `"\n## Resolution\n- x"`. The risk panel's "(single line only)" did not make it into plan.toml. A check that only rejects `## ` lets a reason like `"gave up\nstatus: open"` through. That writes a second status line into the header, and t-1 has no contract for a duplicated status line: TestParseProblems covers headings and unrecognised values, not two `status:` lines. A closed session could then read open again and come back into the status and reentry nudges, which breaks c-6.
  Suggestion: state in t-4 that any `\n` or `\r` in the reason errors, add a `"x\nstatus: open"` row to TestCloseTextReason, and add a two-status-lines row to TestParseProblems.

- [test-contract] t-4 never defines what RuleAddCommand's "flattens Prevention to one line" keeps. The risk panel said "markers and comments stripped", but plan.toml dropped that. t-5's contract then says the stored rule can be "one starting `- `", which implies list markers are kept. No row pins whether `<!-- -->` comments or fenced blocks are removed. Take the likely case: the agent writes prose under the template's placeholder comment without deleting it. The printed `dross rule add` would then carry the placeholder text. Every current contract (no newline, exact argv round-trip) still passes.
  Suggestion: write the flatten rule into t-4's description (comments and fences dropped, same as Parse's emptiness rule; markers kept or stripped, pick one). Add a TestRuleAddCommandShellOracle row with a Prevention of comment + prose that yields only the prose. Make t-5's "starting `- `" row agree with that choice.

- [test-contract] t-7 checks c-9's "tree returned to its pre-session state" against a `git status --porcelain` snapshot. Porcelain ignores content. If a file was already modified before the session (the normal mid-phase case: a task in progress with uncommitted edits), it stays ` M` whatever a probe leaves in it. A probe that does not fully revert its instrumentation therefore passes the check. The prompt also forbids fenced `git stash` and `git checkout -- .`, so reverting relies entirely on the agent undoing its own Edits, and this snapshot is the only thing checking that.
  Suggestion: have the snapshot include a content hash, for example porcelain plus `git diff HEAD | shasum -a 256`, compared before and after each probe. Pin that in the TestDebugPromptRequirements tree-restore subtest.

- [test-contract] t-7 says "session content in a commit, PR body or board issue is forbidden". The locked prevention_rule route sends the Prevention text into `dross rule add`, whose default scope writes the tracked `.dross/rules.toml`, and this repo is public. So the prompt has two instructions that conflict. An agent will either refuse to offer the rule because it is session content, or offer a Prevention that quotes captured output.
  Suggestion: make the publication ban name the rule route as the one sanctioned exit, and require Prevention to be a rule statement with no captured output, paths or tokens. Pin both in TestDebugPromptRequirements.

- [test-contract] No task specifies what `close --fixed` does when Parse reports Problems. Take a session with a duplicated `## Resolution` heading, one item under each. If the parser sums the two sections, the gate counts 2 signals and passes on a file the parser itself flags as malformed. The prompt treats a Problem as BLOCKED (t-7). The CLI boundary does not (t-4, t-5).
  Suggestion: decide whether FixedCloseGaps refuses on any Problem (or names the Problem as a gap), and add a duplicated-heading row to TestFixedCloseGaps or TestDebugCloseFixedRefusal.

- [test-contract] t-8 edits docs/dross.1 in three sections (CLI COMMANDS, SLASH COMMANDS/Continuity, FILES) with no contract. Its README contracts don't require the `dross debug {new,list,close}` row to exist: TestReadmeAdvertisesOnlyRealCommands checks over-claims only, so deleting the row stays green. Given the README-sync convention, two of t-8's deliverables can disappear without a red test.
  Suggestion: extend TestReadmeDocumentsDebugSessions to require the `dross debug` command row and a `dross debug` / `.dross/debug` mention in docs/dross.1. This follows the existing README + dross.1 loop pattern in local_test.go and redproof_set_test.go.

No new file collides with an existing one.
- [locked-decision] session_format says the CLI reads "only the header status line, the fixed headings and the list-item markers". The plan goes past that in two places. Reading Prevention's body for RuleAddCommand is required by c-7, so the conflict is inside the spec, not caused by the plan. Deduping whitespace-identical Resolution items (t-1) is the plan's own choice. synthesis.md D-8 records it, but plan.toml does not, and it moves the CLI slightly toward judging independence, which close_gates leaves to the prompt. Not blocking: it is still a count.
- [coverage] `dross debug list` shows failures since the last re-plan, not the lifetime total (synthesis D-7). c-2 just says "failed-fix count". A session that was just re-planned shows 0 after three failed fixes. This is a deliberate choice, recorded here so the user sees it.
- [granularity] t-7 touches 6 files, over the 5-file heuristic. Splitting it would be worse. TestInteractionCoverageFailClosed, TestSubagentOffloadAuditCoversEveryPrompt and TestCommandsPromptsParity are fail-closed, so the shim, prompt and both audit docs have to land in one commit to stay green.
- [wave-order] t-8's contracts only need t-5. Its dependency on t-7 comes from what it documents: the footer-audit "Footer-bearing" row records t-7's fresh-session-next choice. That row is classification of the new prompt, which t-7 otherwise owns (interaction-audit, subagent-offload-audit). Accept the order, or move the row into t-7 and let t-8 run in wave 4.
- [status-output] Status's last line must stay byte-equal to the reentry envelope (TestStatusDebugByteEqualReentry). As a result, `dross status` names the newest open session twice: once on the new `debug:` line and again in the reentry clause. TestStatusDebugOneLine ("exactly one line naming both") passes only because the reentry clause names one session plus "(+N more)". With a single open session, two lines name it. This is consistent with c-2 and c-3 but worth knowing.
- [reuse] t-7 writes its own "no raw `<runtime.test_command>` line, probes run `dross test`" assertion. Appending `debug.md` to `suiteRunningPrompts` in prompt_test_command_test.go would get the same two-way check from TestPromptsRunDrossTest without a parallel copy.
- [runtime] t-7 does not cover a mid-phase /dross-debug while a pair-mode task is in_progress. The pair-approval gate claims every Edit/Write outside .dross/ there, so whether a probe's temporary edit is allowed depends on whether the current task's approval exists at HEAD. The prompt says nothing about this. It is not a criterion, so not flagged.
- [forbidden-actions] No rule violations. r-01 (`make install` after prompt edits) is stated in t-7. runtime.mode is native, so plain `go test` is fine. There is no global rules.toml.
- [strengths] Putting parsing, store and close logic in a pure `internal/debugsession` package keeps them inside coverfloor and lets gremlins kill their mutants without the ~600s internal/cmd suite. The t-1 contracts are adversarial where it matters: an off-by-one replan table, section scope, fences, multi-line comments, CRLF and indented sub-bullets.
- [strengths] The locked session_tracking decision is enforced with mechanism, not prose. A self-ignoring `.dross/debug/.gitignore` is verified with `git check-ignore` before the write, including a hostile `!*` case. TestDebugSessionNoChoreRide proves autoCommitDrossDirt cannot pick a session up. The MachineLocal declaration is checked by the existing enum tests.
- [strengths] Every c-9 requirement maps to a named prompt subtest. Prompt↔parser vocabulary parity is checked against exported constants, and the rule command is checked with a real `/bin/sh -c` oracle (single and double quotes, `$(…)`, backticks, `!`, backslash, leading `- `). Most LLM plans pin prompts with "the prompt mentions X"; these are stronger.

## Summary
The plan covers every criterion, respects every locked decision and has unusually adversarial contracts. It can go ahead once the four contract gaps are tightened: reason single-line, flatten rule, probe-restore snapshot, and the Prevention publication carve-out.
