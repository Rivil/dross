## Decisions locked

- **update_tool** 🔒 — Dependabot (GitHub-native), not Renovate. *(No third-party app with repo write access; matches the hardening posture of supply-chain-currency. Its blind spots (run-block pins) are deferred, not papered over.)*
- **target_branch** 🔒 — PRs target `main` (the default); no `target-branch` override. *(Zero per-milestone config churn; a stale milestone target would silently no-op. The occasional go.sum conflict at milestone-merge time is resolvable and CI re-runs.)*
- **security_bump_release** 🔒 — A merged currency bump rides the next phase ship. A merged security bump is released by hand via release.yml `workflow_dispatch` with the next patch tag; documented in the phase. *(release.yml tags only when project.toml's version changes, so a bot merge cuts no release by construction. Auto-tagging every main merge would break the 'quick task cuts no release' rule — not this phase's call.)*
- **auto_merge** 🔒 — No auto-merge; every Dependabot PR is merged by hand. *(`main` has no branch protection or required checks, so nothing would gate an auto-merge. Revisit once main-branch-protection lands.)*
- **npm_fixture_scope** 🔒 — The Stryker fixture is an `npm` ecosystem entry, grouped with cooldown like the others. *(CI runs `npm audit --audit-level=high` against it with no automated fix path; a bump PR runs the stryker e2e job, so a fixture break is visible before merge.)*
